## 1. 执行摘要与范围

### 1.1 当前项目事实

本 PRD 以当前代码库为约束，不假设已有服务端定时任务或通知能力。代码审查确认：

- Task.type 当前只接受 single 与 progress；普通任务以 completed 表示完成，进度任务以 count === targetCount 表示完成。

- 任务时间由 startDate 与 endDate 共同表示；两者要么同时为空，要么同时存在，今天/本周看板按时间区间重叠计算。

- 桌面端采用左侧时间看板、中央任务列表、右侧抽屉式新建表单；移动端采用顶部时间分段、底部导航和浮动新建按钮。

- Firestore 路径为 users/{uid}/tasks/{taskId} 与其 logs 子集合；客户端使用本地优先实时同步，并保留操作日志。

- 现有复制、类型切换、进度加减、隐藏已完成、全部/今天/本周筛选应继续可用。

### 1.2 目标

- 让普通任务与进度任务都能选择是否重复，并明确创建、完成、逾期、编辑、删除、撤销和结束后的行为。

- 为桌面端提供适合键鼠的重复规则编辑器，同时给出与现有移动布局相容的单列交互。

- 允许一个任务关联 0–10 个标签，支持创建、选择、移除、重命名、合并、删除和颜色管理。

- 提供按标签查看任务的看板，并支持多标签“全部匹配 / 任一匹配”。

- 保持现有离线优先、跨设备同步、历史日志与旧数据兼容。

### 1.3 非目标（本期不做）

- 系统推送通知、闹钟、提前提醒、位置提醒与联系人触发；本期只扩展任务调度和看板展示。

- “完成后再过 N 天”式完成时间锚定、连续打卡、连胜、补签和习惯统计。iOS 原生也不提供完成时间锚定。

- 预生成无限未来实例、月历视图、资源排班与多人协作分配。

- 自然语言解析（如“每周三下午五点”）与第三方日历同步。

### 1.4 P0 / P1 范围

| **优先级** | **包含** | **不包含** |
| --- | --- | --- |
| P0 | 常用预设、自定日/周/月/年、截止日期、普通/进度叠加、单活动实例、标签与标签看板、标签管理、迁移与同步 | 小时级重复、批量打标签、复杂组合智能看板 |
| P1 | 小时级重复、月度序数工作日、多月组合、批量打标签、固定组合看板、导入/导出标签 | 通知、位置、协作、完成时间锚定 |

### 2.4 对本项目的可复用结论

- 复用“日期/时间 → 重复 → 频率 → 结束条件”的渐进式设置路径，用户只有在需要时才看到复杂规则。

- 复用“单个可操作实例”的轻量模型，避免列表被未来几十次任务淹没。

- 复用固定计划锚点；把完成时间锚定明确列为未来能力，而不是暗中混用两种语义。

- 复用标签浏览器和多标签筛选，但根据 PC 空间优势提供更持续可见的标签侧栏和管理页。

- 对 iOS 原生含糊之处（逾期跳过、进度重置、撤销）给出可测试的产品规则。

## 3. 产品概念模型与设计决策

### 3.1 四个正交概念

| **概念** | **定义** | **允许值 / 示例** |
| --- | --- | --- |
| 逻辑任务（Task / Series） | 用户长期看到并编辑的任务；重复任务时同时是一个系列。 | “每周整理周报” |
| 任务类型（TaskType） | 决定完成机制，不决定是否重复。 | single / progress |
| 重复规则（Recurrence） | 决定当前实例完成后下一次何时出现。 | 每周一、三；每月最后一个工作日 |
| 当前实例（Occurrence） | 系列当前唯一可操作的时间窗口和状态。 | 2026-08-03 09:00–17:00，count 2/5 |
| 标签（Tag） | 跨时间看板的稳定分类，可多个。 | #工作、#家庭、#等待 |

**不变量：** `Task.type` 永远只表示 `single` / `progress`；`recurrence = null` 表示不重复，`recurrence ≠ null` 表示重复；`tagIds` 是 0–10 个稳定标签 ID。

### 3.2 已确定的产品决策

| **编号** | **决策** | **说明** |
| --- | --- | --- |
| D-01 | 重复不是第三种类型 | 普通任务和进度任务均可开启/关闭重复；类型切换逻辑继续独立。 |
| D-02 | 单活动实例 | 不预生成未来任务；列表与计数只包含当前实例。完成历史进入明细记录。 |
| D-03 | 固定计划锚点 | 重复规则锚定当前实例的计划开始时间，而不是 completedAt。 |
| D-04 | 逾期不补账 | 逾期实例完成后，下一次取严格晚于完成时刻的最近计划点；已经错过的中间计划点不补建。 |
| D-05 | 进度按实例重置 | 进度任务每次从 0 开始，targetCount 继承；达到目标即完成本次并滚动。 |
| D-06 | 标签归属逻辑任务 | 标签不是某一次实例的临时属性；修改标签立即影响当前与未来实例。 |
| D-07 | 无时间不可重复 | 重复任务必须有完整 startDate/endDate；选择重复时若为空，先引导设置时间。 |
| D-08 | 时间范围整体平移 | 规则计算下一次 startDate，endDate 按当前持续时长整体平移。 |

### 3.3 典型用户故事

- 作为个人用户，我可以让“每天喝水”成为重复普通任务，完成后自动显示下一天。

- 作为项目执行者，我可以让“每周完成 5 次客户跟进”成为重复进度任务，每周自动重置 0/5。

- 作为桌面用户，我可以在新建抽屉中用常用预设快速设置，也可以展开自定规则并预览未来三次。

- 作为整理者，我可以为任务添加“工作、等待、重要客户”等多个标签，并从标签看板跨全部/今天/本周查看。

- 作为维护者，我重命名或合并标签后，不需要逐条更新任务。

## 4. 重复任务功能需求

### 4.1 创建与编辑入口

重复设置放在“时间范围”之后、“标签”之前。默认折叠为一行“重复：不重复”；点击后打开选择面板。开启重复前必须存在合法的开始/结束时间。

- 常用项：不重复、每天、工作日、周末、每周、每两周、每月、每 3 个月、每 6 个月、每年、自定。P1 在设置具体时间且持续时长小于间隔时显示“每小时”。

- 选择预设后立即显示自然语言摘要，例如“每 2 周的周一、周三 · 永不结束”。

- 选择“自定”进入三段式编辑器：频率与间隔 → 具体日 → 结束条件；底部实时预览未来 3 次时间窗口。

- 若 startDate/endDate 为空，点击重复显示内联提示“先设置时间范围”，并把焦点移到开始时间。

### 4.2 规则能力

| **显示项** | **规则表达** | **行为** |
| --- | --- | --- |
| 每天 | interval = 1 day | 每天同一墙上时钟时间 |
| 工作日 | weekly + 周一至周五 | 遇周末跳到周一 |
| 周末 | weekly + 周六、周日 | 每周两次 |
| 每周 / 每两周 | weekly interval 1 / 2 | 默认选中开始日期的星期；可多选星期 |
| 每月 / 3 月 / 6 月 | monthly interval 1 / 3 / 6 | 默认按开始日期的日；不存在该日的月份跳过 |
| 每年 | yearly interval 1 | 默认按开始月日 |
| 自定日 | daily interval 1–999 | 每 N 天 |
| 自定周 | weekly interval 1–999 + weekdays | 至少选择一个星期 |
| 自定月 | monthly interval 1–999 + 月日或序数星期 | P0 单月日；P1 多月日与最后工作日 |
| 自定年 | yearly interval 1–999 + 月份/日期 | P0 单月日；P1 多月份与序数星期 |
| 结束 | never / until | until 为包含边界：下一次 start ≤ 截止日才生成 |

### 4.4 完成与推进算法

**确定性公式：** `nextStart` = 重复规则中第一个严格晚于 `max(currentStart, completedAt)` 的计划点；`nextEnd = nextStart + 当前实例持续时长`。若 `nextStart` 超过 `until`，则 `seriesState = ended`。

- 提前完成：例如周一任务在周日提前完成，仍取下一个计划周一，不从周日重新计时。

- 逾期完成：例如每天任务周一到期、周三完成，周二/周三已错过点不补建，下一次为周四。

- 月末：规则为每月 31 日时，二月没有合法日期则跳到下一个含 31 日的月份；不自动压到二月最后一天。

- 夏令时：在任务保存的 IANA 时区中保持墙上时钟时间；不存在的本地时间顺延到该日第一个有效时刻，重复出现的时间取第一次。

- 进度任务：最后一次 +1 与“完成本次并滚动”是同一原子业务动作；不能先把 count 写成 target 再由定时器异步滚动。

### 4.5 状态转换

| **起始状态** | **事件** | **数据动作** | **结果** |
| --- | --- | --- | --- |
| 非重复进行中 | 完成 | completed = true 或 count = target | 进入已完成组 |
| 重复当前实例进行中 | 完成 / 达到目标 | 写 occurrence 完成记录；计算下一次 | 存在下一次→重置并保持活动；否则系列结束 |
| 重复当前实例进行中 | 跳过本次 | 写 skipped 记录；计算下一次 | 同上 |
| 刚滚动的新实例 | 撤销 | 恢复上一个实例与状态，写 undo 记录 | 仅新实例无后续变更时允许 |
| 重复系列活动 | 关闭重复 | 清除 recurrence，保留当前窗口 | 成为普通非重复任务 |
| 重复系列活动 | 删除本次及以后 | 删除任务文档；历史按现有删除策略处理 | 不再显示 |
| 重复系列结束 | 取消完成 | 恢复最终实例为活动；不自动恢复已过截止日期之外的未来实例 | 活动或等待用户改截止日 |

### 4.6 编辑与删除范围

为控制实现复杂度，只有会改变计划链的操作出现范围选择。标题、描述、类型、目标次数与标签均视为逻辑任务属性，直接作用于当前与未来；历史快照不回写。

| **操作** | **选项** | **效果** |
| --- | --- | --- |
| 修改当前开始/结束 | 仅本次 | 记录 current override；完成后恢复基础规则 |
| 修改当前开始/结束 | 本次及以后 | 更新锚点和规则，未来从新时间继续 |
| 修改重复规则/截止日期 | 本次及以后 | 不提供仅本次；保存前预览三次 |
| 删除 | 跳过本次 | 保留系列和历史，立即滚动下一次 |
| 删除 | 删除本次及以后 | 删除活动系列；确认框显示影响 |
| 关闭重复 | 保留当前实例 | 清除未来计划，当前任务不自动完成 |

## 5. PC 与移动端交互规范

### 5.1 桌面端新建/编辑抽屉

- 保留现有右侧抽屉宽度与单列结构。时间范围下增加“重复”行；未开启时不显示高级字段。

- 点击“重复”打开锚定在该行下方的 popover：左侧常用预设，右侧自定规则；窄桌面退化为单列弹层。

- 自定规则使用原生按钮组、数字输入、星期多选、月日/序数切换、结束日期；不使用难以键盘操作的滚轮控件。

- popover 底部固定显示规则摘要和未来 3 次预览；按 Escape 关闭但不丢失已选值，再次 Escape 触发抽屉原有关闭逻辑。

- 标签控件位于重复后：多选 chip 输入，输入时匹配已有标签，Enter 选择第一项，输入新名称时提供“创建 #名称”。

### 5.2 桌面端任务列表与详情

- 任务行在时间下方或右侧状态区显示循环图标与短摘要（如“每周一、三”）；标签显示最多 3 个，超出显示“+N”。

- 悬停快捷完成沿用现状。重复普通任务完成后同一行更新为下一时间并显示 toast：“已完成本次 · 下一次 8/10 09:00｜撤销”。

- 重复进度任务达到目标时动画收束，随后 count 重置为 0；toast 明确“本次 5/5 已完成，下一次已开始”，避免被误解为丢失进度。

- 详情页增加“重复计划”卡片与“重复记录”分组；变更记录继续保留字段修改，实例记录按 occurrenceKey 聚合。

- 左侧看板在“本周”后新增可折叠“标签”区；常用标签按用户顺序显示，管理入口位于区标题菜单和设置页。

### 5.3 移动端

- 新建与详情仍为全屏单列。点击“重复”进入次级页面/底部全高 sheet，顶部有返回与完成，表单顺序与桌面一致。

- 星期使用 7 个等宽圆角按钮；间隔使用数字输入加减；月/年复杂选择分段展开，底部固定显示摘要。

- 标签选择使用可搜索底部 sheet，已选标签置顶；任务详情内标签 chip 可单独删除。

- 现有“全部/今天/本周”分段不扩成四段，以免拥挤。顶部搜索旁增加“看板/筛选”按钮，打开包含时间看板与标签看板的 sheet。

- 完成重复任务仍保留左右滑动；滚动到下一次后用底部 snackbar 提供撤销，不依赖悬停。

### 5.4 文案规范

| **场景** | **推荐文案** | **说明** |
| --- | --- | --- |
| 未开启 | 不重复 | 不要使用“普通重复”或“重复类型” |
| 预设摘要 | 每天 / 每个工作日 / 每 2 周的周一、周三 | 优先自然语言，不暴露 RRULE |
| 结束摘要 | 永不结束 / 重复至 2026-12-31 | 截止日期包含当天 |
| 普通完成 | 已完成本次 · 下一次 8 月 10 日 09:00 | 附“撤销” |
| 进度完成 | 本次 5/5 已完成，下一次已从 0/5 开始 | 避免“进度被清空” |
| 删除 | 跳过本次 / 删除本次及以后 | 不要用含糊的“删除全部” |
| 标签筛选 | 匹配全部 / 匹配任一 | 默认匹配全部 |

### 5.5 可访问性与键盘

- 重复行、标签 chip、星期按钮和颜色选项都必须有可感知名称、选中状态与焦点环；不可只靠颜色表达。

- popover 焦点被限制在弹层内；关闭后回到触发按钮。Enter/Space 选择，方向键在分段控件中移动，Escape 分级关闭。

- 规则摘要使用 aria-live=polite；完成滚动后的 toast 也必须由读屏播报。

- 触控目标至少 44×44 CSS px；尊重 prefers-reduced-motion，进度重置不使用强制动效。

## 6. 标签、标签管理与标签看板

### 6.1 标签定义与约束

| **属性** | **规则** |
| --- | --- |

| 名称 | 1–24 个 Unicode 字符；允许中文、字母、数字、空格、连字符、下划线；UI 不要求用户输入 #。 |
| 规范化 | NFKC → trim → 连续空白折叠为一个空格 → locale-insensitive 小写，用于唯一性。 |
| 唯一性 | 同一用户内 normalizedName 唯一；“工作”与“ 工作 ”视为同一标签。 |
| 颜色 | 从 8 个无障碍预设色中选择；颜色仅辅助识别，同时始终显示名称。 |
| 排序 | 默认按用户自定义顺序；新标签追加。标签看板可按名称/任务数临时排序。 |

### 6.2 任务内添加标签

- 新建/详情中的标签选择器支持搜索现有标签、多选、移除和即时创建。已选标签不能重复。

- 输入名称完全匹配现有标签时只显示选择，不再显示创建；达到 10 个后禁用新增并提示上限。

- 创建新标签时使用默认颜色；用户可在设置的标签管理页修改颜色。

- 保存任务与创建标签分两个可恢复动作：标签先创建成功，再保存 tagIds；若任务保存失败，新建标签仍保留在标签管理中。

- P1 支持任务列表多选后批量添加/移除标签。

### 6.3 标签看板

- 桌面左侧看板新增“标签”区，显示最多 8 个置顶/常用标签与当前活动任务数；点击“全部标签”进入标签浏览器。

- 单标签路由建议为 /tasks/tags/{tagId}；组合筛选建议用 /tasks/tags?ids=a,b&match=all，避免把标签混入 BoardScope。

- 单标签看板展示该标签跨全部日期的任务，继续按“进行中/已完成”分组；顶部可叠加时间筛选（全部/今天/本周）。

- 选择多个标签时默认“匹配全部（AND）”；用户可切换“匹配任一（OR）”。选择结果以 chip 固定在标题下方并可逐个移除。

- 标签任务数按逻辑任务/当前实例计数，不按历史 occurrence 次数计数；隐藏已完成偏好继续生效。

- 搜索同时匹配任务标题、描述与标签名。标签被删除时，打开的标签路由显示“标签已删除”并返回全部标签。

### 6.4 标签管理

- 设置页新增“标签管理”：列表显示颜色、名称、活动任务数、更新时间与更多菜单；支持新建、重命名、改色、拖拽排序、删除。

- 重命名为未使用名称：仅更新标签文档，任务 tagIds 不变。重命名为已存在名称：提示“合并标签”，将源标签 ID 批量替换为目标 ID。

- 删除前显示受影响任务数；确认后标签立即从 UI 隐藏，后台分批清理任务中的 tagId。删除不删除任务。

- 重复任务历史记录保存当时的标签名称快照；标签后续重命名/删除不改写既有审计记录。

- 离线时允许新增/改名/改色；合并与删除属于跨多文档操作，离线时排队但在同步完成前显示“处理中”。

## 7. 数据模型、同步与安全规则

### 7.1 推荐数据模型（兼容现有 Task）

为降低改造风险，保留现有顶层 title、description、startDate、endDate、type、targetCount、count、completed 字段。对于重复任务，这些顶层状态始终表示“当前实例”；新增字段描述系列与幂等推进。

| **字段** | **类型** | **说明** |
| --- | --- | --- |
| schemaVersion | number | 旧数据默认为 1；新写入为 2。 |
| tagIds | string[] | 默认 []，最多 10 个。 |
| recurrence | map \| null | frequency、interval、byWeekdays、byMonthDays、ordinalWeekday、byMonths、end、timeZone、anchorStart、durationMinutes。 |
| seriesState | active \| ended \| null | 非重复为 null；重复系列活动或已结束。 |
| currentOccurrenceKey | string \| null | 由 seriesId + 计划开始时间确定，完成/跳过的幂等键。 |
| occurrenceSequence | number | 从 1 递增，只用于展示/诊断，不参与主键。 |
| lastAdvanceMutationId | string \| null | 客户端操作幂等与冲突提示。 |
| updatedAt | timestamp | 沿用服务端时间；计划计算使用存储时区与客户端完成时刻。 |

### 7.2 recurrence 结构

建议结构（示意，不是最终 TypeScript 定义）：

```ts
recurrence: {

  frequency: 'daily' | 'weekly' | 'monthly' | 'yearly' | 'hourly',
  interval: number,
  byWeekdays?: number[],        // 1=周一 … 7=周日
  byMonthDays?: number[],       // 1…31；不存在则跳过
  ordinalWeekday?: { ordinal: 1 | 2 | 3 | 4 | -1, weekday: 1 | 2 | 3 | 4 | 5 | 6 | 7 },
  byMonths?: number[],          // 1…12
  end: { kind: 'never' } | { kind: 'until', date: 'YYYY-MM-DD' },
  timeZone: string,             // IANA，例如 Asia/Shanghai
  anchorStart: string,          // 首次/重新锚定的本地日期时间
  durationMinutes: number
}
```

注：Firestore 不支持 undefined，保存前必须移除未使用字段；规则摘要应由结构化字段生成，不能作为唯一事实来源。

### 7.3 标签集合

| **路径** | **字段** | **说明** |
| --- | --- | --- |
| users/{uid}/tags/{tagId} | name、normalizedName、color、sortOrder、createdAt、updatedAt、deletedAt? | tagId 永久稳定；重命名不改 ID。 |
| users/{uid}/tagNameClaims/{nameKey} | tagId、normalizedName、createdAt | 防止多端同时创建同名标签；重命名时原子迁移 claim。 |
| tasks/{taskId}.tagIds | string[] | 只存 ID，不冗余名称；展示时与 tags 映射。 |

### 7.4 重复实例记录与日志

继续复用 tasks/{taskId}/logs，但扩展 type = recurrence，并在 payload 中保存 occurrence 快照：scheduledStart、scheduledEnd、result、completedAt、count、targetCount、title、tagNames、mutationId。跳过与撤销新增独立日志，不修改旧日志。

**为何不预生成实例：** 现有看板客户端订阅全部任务；预生成会放大读取、排序、规则和离线冲突。滚动当前实例 + 不可变完成日志最符合当前架构和 iOS 的单实例心智。

### 7.5 离线与多端并发

- 完成/跳过重复实例使用一个 writeBatch：创建确定 ID 的完成账本/日志（仅允许 create）并更新任务到下一实例。第二台设备对同一 occurrenceKey 的重复写入会因日志已存在而整体拒绝并回滚。

- 客户端先乐观展示下一次；冲突时实时监听恢复首个成功结果，并提示“该次任务已在另一设备处理”。

- 普通进度 +1 可继续使用 increment；触达 target 的最后一步必须走“完成并推进”批次，禁止同时 increment 和推进。

- lastAdvanceMutationId 防止同一客户端重试造成重复 toast；mutationId 仅用于幂等，不上传用户内容。

- 标签删除/合并分批处理时，任务可以短暂持有失效 tagId；展示层忽略无对应活跃 tag 的 ID，并由后台重试清理。

### 7.6 Firestore 规则与索引

| **项** | **要求** |
| --- | --- |
| Task 字段 | 扩展 hasOnly/hasAll；验证 tagIds 为 ≤10 的字符串列表，recurrence 字段组合与 type/count 不变量。 |
| 日志 | 允许 type in ['update','progress','recurrence','tag']；完成账本只允许 create，禁止 update。 |
| 标签 | tags 与 tagNameClaims 仅 owner 可读写；名称长度、颜色枚举、时间戳和字段白名单。 |
| 删除 | 删除标签不应由规则直接级联；客户端批次清理，悬空 ID 对任务有效性不构成阻断。 |
| 索引 | 当前全量订阅后本地过滤可不新增；若改服务端标签查询，需 tagIds array-contains + createdAt/updatedAt 复合索引。 |
| 部署顺序 | 先发布兼容 v1/v2 的规则与索引，再发布客户端；稳定后再收紧旧字段策略。 |

## 8. 迁移、兼容与发布方案

### 8.1 旧数据兼容

- 读取：缺少 tagIds 时按 []；缺少 recurrence/currentOccurrenceKey/seriesState 时按非重复；缺少 schemaVersion 时按 v1。

- 写入：旧任务第一次被编辑时按 v2 补齐，不需要一次性全库迁移；这降低规则回滚与离线缓存风险。

- 类型：既有 single/progress 数据和完成判断不变；仅重复任务使用新的滚动完成路径。

- 时间：既有无时间任务保持不变；用户首次开启重复时写入当前浏览器 IANA 时区。

- 历史：既有 logs 原样展示；新 occurrence 记录从功能上线后开始，不伪造过去重复历史。

### 8.2 路由与前端类型改造

- 保留 BoardScope = 'today' | 'week' | 'all'；新增 BoardFilter 联合类型，不把 tagId 塞进 BoardScope。

- AppRoute 新增 tag-board 与 tags-browser；桌面/移动共享同一 URL，浏览器后退可恢复筛选。

- TaskDraft 增加 recurrence 与 tagIds；TaskInfoFields 增加可编辑系列字段；normalizeTaskDraft 验证规则与标签上限。

- taskOverlapsScope 继续只读取当前实例的顶层 startDate/endDate，因此原有今天/本周测试可复用。

- filterAndSortTasks 增加 selectedTagIds/matchMode，并把标签名称纳入搜索索引。

### 8.3 建议迭代顺序

| **阶段** | **主题** | **交付** | **发布** |
| --- | --- | --- | --- |
| 阶段 0 | 类型/算法 | 定义 RecurrenceRule、nextOccurrence 单元测试、标签规范化、读适配器。 | 不改 UI |
| 阶段 1 | 数据与规则 | Firestore v2 规则、日志、标签集合、离线幂等。 | 内部开关 |
| 阶段 2 | 重复 P0 | 新建/详情、列表摘要、普通/进度滚动、撤销、结束。 | 灰度 10% |
| 阶段 3 | 标签 P0 | 标签选择、管理、侧栏与标签看板、AND/OR。 | 灰度 50% |
| 阶段 4 | 质量 | 跨时区/DST、多端并发、离线、可访问性、性能。 | 全量 |
| 阶段 5 | P1 | 小时级、复杂月/年、批量标签、组合看板。 | 按使用数据 |

### 8.4 回滚策略

前端功能开关关闭时，v2 客户端仍能读取 recurrence/tagIds，但不允许创建新规则；已存在重复任务继续通过后台兼容逻辑推进，避免“关闭 UI 等于停止用户任务”。若必须完全回滚，先暂停新建，再导出活动系列并把当前实例降级为非重复任务，不能直接删除 recurrence 字段。

## 9. 指标、风险与非目标

### 9.1 埋点（不含用户内容）

| **事件** | **允许属性** | **用途** |
| --- | --- | --- |
| recurrence_created | frequency、isCustom、taskType、endKind | 重复使用率 |
| recurrence_occurrence_completed | taskType、wasOverdue、daysLateBucket | 完成与逾期 |
| recurrence_advanced | frequency、skippedPastCountBucket、seriesEnded | 算法质量 |
| recurrence_undo | secondsAfterAdvance、success | 误操作率 |
| tag_attached | tagCountAfter、createdNew | 多标签采用 |
| tag_board_opened | selectedCount、matchMode、timeScope | 标签看板价值 |
| tag_renamed/merged/deleted | affectedTaskCountBucket | 管理成本 |

禁止上传任务标题、描述、标签名称、精确时间或用户 ID 明文；只上传枚举与分桶。

### 9.2 成功指标

- 上线 30 天内：使用重复的活跃用户占创建过任务用户 ≥ 15%；重复实例成功推进率 ≥ 99.5%。

- 重复完成后 60 秒内撤销率 < 2%，否则优先复查进度重置与文案。

- 标签用户中，标签看板 7 日回访率 ≥ 30%；平均每个已打标签任务的标签数 ≥ 1.3。

- 同步冲突导致的重复推进/丢失推进为 0；安全规则拒绝率不高于现有基线 +0.2%。

### 9.3 主要风险与缓解

| **风险** | **等级** | **缓解** |
| --- | --- | --- |
| 进度达到目标瞬间切到 0/目标，被理解为数据丢失 | 高 | 完成动画、明确 toast、10 秒撤销、实例历史。 |
| 多端同时完成同一实例导致重复推进 | 高 | 确定 occurrenceKey、create-only 账本、批次原子性、冲突回滚。 |
| 月末/DST 计算不一致 | 高 | 独立纯函数、IANA 时区、规则预览与固定测试矩阵。 |
| 标签删除级联任务过多 | 中 | 稳定 ID、软删除、分批清理、悬空 ID 容错。 |
| 侧栏标签过多影响导航 | 中 | 显示前 8、折叠、全部标签浏览器、用户排序。 |
| 把重复误解成第三种任务类型 | 中 | UI 放在时间后，文案使用“重复设置”而不是“任务类型”。 |
| 功能开关回滚让系列停止 | 高 | 推进逻辑与编辑 UI 解耦，保留兼容读写路径。 |

### 9.4 已定默认与未来候选

**本期默认：** 固定计划、逾期不补账、一个活动实例、标签默认 AND、复制默认不继承重复。产品评审若不提出异议，研发按此实现。

未来候选：完成后 N 天、暂停系列、跳过节假日、重复通知、日历视图、固定组合智能看板、打卡统计。任何候选都不应改变本期数据含义；应通过新增 scheduleMode 或独立视图扩展。

## 附录 A. 术语与规则示例

### A.1 术语

| **术语** | **定义** |
| --- | --- |
| 逻辑任务/系列 | 重复前后保持同一 taskId 的用户对象。 |
| 当前实例 | 当前唯一可完成或推进的一次计划。 |
| 计划锚点 | 重复规则用于计算日期的原始 startDate，不是完成时间。 |
| 固定计划 | 下一次由日历规则决定；本期唯一 scheduleMode。 |
| 逾期不补账 | 错过的中间计划点不生成独立待办，完成后直接取未来最近点。 |
| 仅本次 override | 只改变当前实例时间，不改变基础重复规则。 |
| 标签看板 | 按 tagIds 聚合当前逻辑任务的视图，不是新的任务容器。 |

### A.2 示例

| **规则** | **输入** | **结果** |
| --- | --- | --- |
| 每天 | 2026-08-03 09:00–09:30；8/5 11:00 才完成 | 下一次 8/6 09:00–09:30；8/4、8/5 不补建。 |
| 每周多日 | 每周一、三 18:00；周三完成 | 下一次下周一 18:00；若周一逾期至周三上午完成，下一次仍是当周周三 18:00。 |
| 每月 31 日 | 1/31 开始 | 2 月跳过，3/31 继续。 |
| 进度重复 | 每周目标 5，周日完成第 5 次 | 写本周 5/5 历史；下周窗口显示 0/5。 |
| 截止日期 | 每月 15 日，重复至 10/01 | 9/15 为最后一次，10/15 不生成。 |
| 标签 AND | A=工作，B=等待；选择 A+B 匹配全部 | 只显示同时拥有 A、B 的任务。 |
| 标签 OR | 同上，切换匹配任一 | 显示拥有 A 或 B 任一标签的任务。 |
